# Handoff: SM-T585 mainline bring-up — audio chunk 1 done, next chunk 2

## Charter

- Scope: mainline Linux 7.3 on the Samsung SM-T585 (`gtaxllte`, Exynos 7870), lean-Linux music
  device; first target USB-MIDI pad controller. See project `CLAUDE.md` for layout, build and
  boot-image facts.
- Mode: interactive bring-up with the user. Flashing BOOT needs no confirmation (2026-10-23).
- Terms: "stage 1" = our kernel + busybox initramfs (no rootfs) with a USB debug shell.
- Record candidates go to the archivist immediately, not at /reflect.

## Conclusions (what holds now)

- Device runs kernel #4, boot image sha1 `facfcd32eca2da3a59bb174731ff52402a3b1be9`.
- Touch + capacitive keys work (stmfts FTS1A096 variant, built in).
- **Audio analysis done:** `docs/audio-analysis-2026-10-23.md` (signal path, gap table, 3 chunks).
  Path: PL330 adma → I2S0 → s1402x mixer → gpz1 pins → RT5659 (i2c5). The 7870 "LPASS" is just
  DISPAUD_CFG resets + PMU pad retention, not the 5433 LPASS.
- **Chunk 1 done (verified on hardware):** RT5659 probes at `2-001b` (i2c5 = i2c-2), ID 10ec/6311.
  DTS: `&i2c5` + `audio-codec@1b`, pin group `codec_gpio` (gpd3-2/3) in `&pinctrl_top`.
  The driver reads unprefixed `ldo1-en-gpios`/`reset-gpios` (binding says `realtek,`-prefixed — mainline mismatch).
- Config: `CONFIG_SOUND/SND/SND_SOC/SND_SOC_RT5659=m` in `kernel/gtaxllte-stage1.config`.
  Modules + `load.sh` in `kernel/out/snd/` (dependency order).
- **Device shell:** `python3 -I kernel/tools/devsh.py "<cmd>" [secs]` via `/dev/ttyACM0`, no pyusb.
  Allowed permanently in `.claude/settings.local.json` (including dd to BOOT).
- Transfer: `python3 -m http.server -b 172.16.42.2 -d kernel/out 8000` (poll before wget);
  on device `wget` into `/tmp` — tmpfs, so modules must be re-fetched after every reboot.
- Flash: `dd if=/tmp/boot-stage1.img of=/dev/mmcblk0p9 bs=1M conv=fsync`, read back with
  `head -c <size> /dev/mmcblk0p9 | sha1sum`, then `reboot -f`.

## Update 2026-10-23 evening: chunk 2 almost done

- Running: kernel #6 Image + DTB from build "#7" (boot sha1 `440dc35a97ef8887f3b380377000a3a01431f459`).
- I2S0 = `samsung,exynos7-i2s1` (downstream "i2s-str" bit layout), clocks iis=APB_AUD,
  i2s_opclk0 = i2s_opclk1 = MI2S_AUD_I2SCODCLKI (opclk1 missing -> NULL mux parent -> ERR_PTR deref -> hard freeze).
- ADMA (PL330) clock is APB_AUD, not APB_AUD_AMP (AMP-only -> bus error).
- DISPAUD_CFG resets read 0 after boot but blocks are dead until pulsed: new reset-simple node
  `samsung,exynos7870-dispaud-reset` @0x148f1000 (+ Kconfig default ARCH_EXYNOS); local patches in
  pl330.c (assert+udelay before deassert) and i2s.c (optional reset pulse in probe).
  PL330 now: Num_Chans-4 Num_Peri-4.
- Test card `i2s0-test` (simple-audio-card, I2S0 -> spdif-dit) registers, pcmC0D0p exists.
- OPEN: `tinyplay sine48k.wav -D 0 -d 0` returns rc=0 instantly, PCM stays "closed", no kernel msg.
  Next: try `-i raw -c 2 -r 48000 -b 16` / tinypcminfo, check hw_params; then measure 3 s play.
- Tools: `kernel/tools/memtool` (no-libc devmem), `kernel/tools/udplog.py` (host UDP syslog sink ->
  `kernel/out/logs/dev.log`; on device `syslogd -R 172.16.42.2:5514; klogd`), tinyalsa in `kernel/out/alsa`.
- Pitfalls: host USB iface name changes per port/replug; reassign IP with
  `nmcli device modify <iface> ipv4.method manual ipv4.addresses 172.16.42.2/24`. Hard freezes leave
  pstore empty. Build modules with the full make (never `M=` without O, it writes into src/).
  devsh first command after idle sometimes garbles: prefix `true;`.
- Power: the earlier PC USB port supplied less than the device draws; battery state unknown (no SM5703 FG driver).
- Lessons: old USB cable crumbled and caused fake "reboots"; AUD_PLL runs 97.5 MHz (48k off by 0.8%).

## Update 2026-10-23 late: chunk 2 DONE

- tinyplay (Alpine tinyalsa 2.0) is broken here; use `kernel/tools/pcmplay` (raw ioctls, nolibc,
  binary `kernel/out/alsa/pcmplay`): `pcmplay /dev/snd/pcmC0D0p sine48k.wav [period] [periods]`.
- Real bug was the rate: AUD_PLL is fractional (K=0x3f55 in CON1) = 98.304 MHz, but mainline
  declared pll_1417x -> reported 97.5 -> i2s psr truncated to /7 -> 54.9 kHz. Local patch:
  `pll_36xx` in `drivers/clk/samsung/clk-exynos7870.c`. Now PSR /8, 12.288 MHz = 256fs, 3 s file in 2958 ms.
- Running: build #7, boot sha1 `3353e4dd964ad54b1122a0298dec53c5c446e8e3`.
- Next: chunk 3 (s1402x mixer driver + audio-graph-card -> RT5659, tone on headphones).
