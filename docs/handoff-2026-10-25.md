# Handoff SM-T585 — 2026-10-25

## Charter
- Scope: SM-T585 (gtaxllte) on our mainline 7.3 fork, now running **postmarketOS edge (systemd)**. Next big step: **U-Boot chainloaded by S-Boot**, to get rid of the 32 MiB BOOT limit.
- Mode: interactive bring-up with the user. Root commands on the host (pmbootstrap, sudo) run in the user's own terminal — `sudo` does not work through Claude's shell or the `!` prefix.
- Terms: "stage 1" = our busybox initramfs boot image (kernel/out/boot-stage1-k*.img); "pmOS" = postmarketOS from our packages in `pmos/`.

## Current device state

- SYSTEM (mmcblk0p19, 3.3 GiB): pmOS, installed via `pmbootstrap install --android-recovery-zip --recovery-install-partition=system --recovery-no-kernel` + `adb shell twrp install`. Subpartitions: p1 pmOS_boot (start 2048, ext2), p2 pmOS_root (start 499712, ext4). **Lineage is broken** until a zip from `lineageOS/` is reflashed; USERDATA untouched (stage-1 Alpine image `/data/gtaxl/rootfs.ext4` still there).
- Access: `ssh -i ~/.ssh/id_ed25519_gtaxllte -o IdentitiesOnly=yes istvan@172.16.42.1` (dedicated passphrase-less key; never use the user's main key). pmOS idle RAM 161 MB used. Only failed unit: nftables.service (kernel lacks nftables).
- Fixes applied by hand on the device (would recur on a reinstall via recovery zip): `/etc/fstab` uses `LABEL=pmOS_root` / `LABEL=pmOS_boot` (installer kept the disk-image UUIDs → 90 s timeout, emergency mode; original in `/etc/fstab.uuid-orig`); `/home/istvan` was mode 777 → sshd ignored keys; `chmod 755 ~`.
- Recovery: Power+Vol-down (2-key reset), then Vol-up+Home+Power = TWRP; `adb push kernel/out/boot-stage1-k33b.img /tmp/` + `adb shell dd if=/tmp/boot-stage1-k33b.img of=/dev/block/mmcblk0p9 bs=1048576` (TWRP dd needs numeric bs). pmOS boot logs: pstore (console-ramoops, pmsg-ramoops) readable from stage 1, not from TWRP.

## Next: U-Boot chainload (user's choice over trimming the kernel)
- Mainline U-Boot supports Exynos 7870 as `exynos-mobile` (S-Boot loads `u-boot.img` from BOOT like a kernel; `make O=.output exynos-mobile_defconfig; make DEVICE_TREE=<dtb> O=.output`; pack with `dtbTool-exynos -o stub-dt.img .output/u-boot.dtb` + `mkbootimg --kernel .output/u-boot-nodtb.bin --dt stub-dt.img`; Vol-down at boot = U-Boot boot menu with fastboot; EFI boot, picks `exynos/<soc>-<device>.dtb` from the root compatible). Docs: https://docs.u-boot.org/en/stable/board/samsung/exynos-mobile/exynos7870.html
- Shallow clone at `src/u-boot` (commit 8649a54d, 2026-10-24; git-ignored for now). Board code `board/samsung/exynos-mobile/`; upstream DTS there: a2corelte, j5y17lte, j6lte, j7xelte, on7xelte — **no gtaxllte**: needs our board DTS (from `src/mainline/arch/arm64/boot/dts/exynos/exynos7870-gtaxllte.dts`) in the U-Boot tree, against U-Boot's `dts/upstream` exynos7870.dtsi.
- Open design question: U-Boot sees only the eMMC GPT partitions, not pmOS's subpartitions inside SYSTEM. The kernel/initramfs/DTB (or an EFI system partition with systemd-boot, as pmaports' `device-samsung-exynos7` does with `deviceinfo_boot_filesystem="fat32"`) must be on a real partition — candidates: CACHE (mmcblk0p20, 200 MB) or a microSD (the user has none yet; the 64 GB card is dead).
- Plan in chunks: (1) build U-Boot for gtaxllte on the host, inspect output; (2) flash u-boot.img to BOOT via TWRP, check it comes up (screen, fastboot over USB) — TWRP stays reachable through S-Boot keys; (3) boot our kernel from a real partition (EFI/systemd-boot or extlinux); (4) switch the pmOS device package to that model.
