## Charter
- Scope: SM-T585 (gtaxllte), mainline 7.3 fork, pmOS edge (systemd) with **GNOME Mobile**, booted by
  **mainline U-Boot chainloaded from S-Boot**. Next (user order 2026-10-26): **real WiFi** and the

## Boot chain (verified on HW 2026-10-26)
- S-Boot → U-Boot in BOOT (mmcblk0p9) → `bootefi bootmgr` → systemd-boot on pmOS_boot (FAT32) →
  kernel (EFI stub). U-Boot maps **USERDATA** (p23) as a disk (blkmap); pmOS image lives there
  (root auto-grew to 24.8 GB). SYSTEM (p19) still holds the old pmOS install (unused).
- U-Boot: `uboot/build.sh` (GNU cross gcc `aarch64-linux-gnu-gcc`; a clang build gave a black
  screen). Sources: `uboot/dts/` (board DTS subset + -u-boot.dtsi), `uboot/env/gtaxllte.env`
  (no `pause`; menu powers off after 60 s; echoes `gtaxllte: bootefi bootmgr` / `... returned`),
  `uboot/gtaxllte.config` (env file; **HS200/HS400 off** — with them U-Boot read the GPT only
  sometimes → hangs/"invalid partition" in fastboot). Current image sha1 a61dbe31…
  **Pending: multi-reboot stability test** of the HS400-off build (first boot OK).
- U-Boot fastboot: reboot, hold Vol-down alone → menu → "Enter Fastboot Mode" (04e8:6602).
  `fastboot flash boot uboot/out/u-boot-gtaxllte.img`, `pmbootstrap flasher flash_rootfs` (userdata).
  If U-Boot cannot see partitions: TWRP (Vol-up+Home+Power) + `adb push` + `dd` to mmcblk0p9.
- U-Boot has no charger driver: don't leave it idle (battery ran flat once).
- ssh: `ssh -i ~/.ssh/id_ed25519_gtaxllte -o IdentitiesOnly=yes istvan@172.16.42.1`
  (key baked in via `pmbootstrap config ssh_keys/ssh_key_glob`).

## Next 1: DSI panel (HX8279D, 1200x1920, id 827903)
- Mainline: DECON + DSIM in exynos7870.dtsi (j6lte uses `&decon`/`&dsi` + exynosdrm),
  `panel-himax-hx8279` needs a new variant; init sequence from downstream
  `drivers/video/fbdev/exynos/decon_7870/panels/hx8279d_param.h` / `hx8279d_lcd_ctrl.c`.
- Brightness = DSI command reg 0xB8 (no backlight IC). Panel power (downstream `decon_board` in
  exynos7870-gtaxl_common.dtsi): regulator LCD_1P8 → gpio_buck_en gpd3-4 high → lcd_rst gpd4-1.
  Our DTS keeps the panel 1.8 V on for the bootloader framebuffer (line ~709).
- DRM_EXYNOS/SAMSUNG_DSIM were kept in the kernel trim for this.
- Optional quick experiment discussed: toggle gpd3-4 and see whether the image comes back.
