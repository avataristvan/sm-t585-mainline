## DSI hang — what is known
- Repro: DSI-on DTB, boot (fine: decon/dsi probe, exynos-drm binds after deferred-probe timeout),
  then `sudo modprobe panel_samsung_gtaxllte_hx8279d` → first exynos-drm atomic commit → SoC freeze.
- Ruled out: SysMMU (CTRL 0x14860000 = 0, bypass; CONFIG_EXYNOS_IOMMU is off), PLL frequency alone
  (500 MHz burst also hangs), simpledrm coexistence alone (fix series removes it — still hangs).
- DSIM/DECON SFRs are readable before the commit (bootloader state: DSIM PLLCTRL 0x00806711 =
  p3 m226 s1, i.e. VCO 1958 MHz /2; mainline 7870 limits m≤125, VCO≤1500 → it picks p3 m113 s0).
- Applied (uncommitted) in src/mainline: Kaustabh Chakraborty's unmerged "[PATCH v5 0/3] Fixes and
  enhancements for Exynos (7870) DSIM bridge driver" (MFLUSH_VS, IRQ-based PLL stable wait,
  aperture removal before component_bind_all). Source: dri-devel via mail-archive msg626858-60
  (lore is bot-gated). Patches in the scratchpad (r626858.patch, r626859.patch).
- With the series, the clean log ends at:
  `enabling [CRTC:41:crtc-0]` → `pre-enabling bridges [ENCODER:42:TMDS-42]` → freeze.
  So the hang is in samsung-dsim pre_enable (power/PLL/link init) or our panel prepare
  (prepare_prev_first), while DECON is already enabled (ENVID set in crtc enable; downstream starts
  DECON last).
- Analysis doc: docs/dsi-hang-analysis-2026-10-27.md (H1 SysMMU now ruled out; H2 PLL reprogram while
  the bootloader link is live; H3 DECON enable order / unwaited SWRESET / VCLK divider).
