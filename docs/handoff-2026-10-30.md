# Handoff 2026-10-30 — cpuidle C2

## Charter

- Scope: PSCI core power-down idle state (C2) on the SM-T585 mainline kernel. Out of scope:
  cluster power-down (CPD), SICD/AFTR/LPM, deep suspend.
- Terms: *C2* = PSCI CPU_SUSPEND power_state 0x10000 (core power-down); *notifier* = the 7870
  CPU PM notifier in `drivers/soc/samsung/exynos-pmu.c` that clears/sets `CPU_LOCAL_PWR_CFG`
  (0xf) in `CPUx_CONFIGURATION` (0x10480000 + 0x2000 + n*0x80, n = cluster*4 + core);
  *OPTION init* = `exynos7870_pmu_init()` (per-CPU `EXYNOS_ARM_CORE_OPTION`, +0x8).
- Mode: HW verification per written plan; user present for runs that can hang
  (reset = Power + Vol-down; boot loop = TWRP).

## Conclusions

- C2 needs two things from the kernel: the notifier (else the core never returns) and the
  OPTION init (else cpu0, which takes all device IRQs, hangs in C2 under IRQ load within a minute).
  Bootloader cpu0 OPTION `0x01010109`; downstream value `0x10010109` on all CPUs.
- Debug plan 2 (results table in docs/cpuidle-plan-2026-10-29.md): F1/F2/F3/F4/F5 stable under
  10 min eMMC + WiFi load, F3b (only cpu0 OPTION reverted) hangs → H4 confirmed, H6 refuted.
  C2 from boot: 3 reboots, load run and an RTC-woken s2idle all clean, no watchdog timeouts.
- The r11 hang loop was on `13550000.mmc` = mmc1 = WiFi SDIO (IRQ 45), not the eMMC.
  A single `13540000.mmc` (eMMC) "Interrupt latency" at ~13.6 s of boot happens without cpuidle
  too and is not a C2 symptom.
- C2 saves only ~8 mA at idle; its value is the frozen s2idle timekeeping.
- On the tablet: a diag build (= r13 code before a comment-only fix) on /boot/vmlinuz,
  `/boot/vmlinuz.good` = r12. Test files removed.
- Uncommitted, ready: src/mainline OPTION init (exynos-pmu.c + exynos-regs-pmu.h; /simplify done,
  checkpatch clean); main repo r13 (`gtaxllte-pmos.config` cpuidle on again, package config =
  r11 config, pkgrel 13, sha512 updated), plan doc results. Nothing pushed.
