# Handoff 2026-10-30 — cpuidle C2

## Charter

- Scope: PSCI core power-down idle state (C2) on the SM-T585 mainline kernel. Out of scope:
  cluster power-down (CPD), SICD/AFTR/LPM, deep suspend.
- Terms: *C2* = PSCI CPU_SUSPEND power_state 0x10000 (core power-down); *notifier* = the 7870
  CPU PM notifier in `drivers/soc/samsung/exynos-pmu.c` that clears/sets `CPU_LOCAL_PWR_CFG`
  (0xf) in `CPUx_CONFIGURATION` (0x10480000 + 0x2000 + n*0x80, n = cluster*4 + core).
- Mode: HW debug per written plan, one variable per run, user present for every run that can
  hang (reset = Power + Vol-down; boot loop = TWRP).

## Conclusions

- Firmware is PSCI v0.1. Plain CPU_SUSPEND without the notifier: the core never returns.
  With the notifier: cores power down and return (PMU status), s2idle freezes timekeeping.
- With C2 enabled from boot the system loses device interrupts under I/O: dw_mmc
  `Interrupt latency, state … (watched …)` loop = eMMC completion IRQ latched in MINTSTS, handler
  never runs. Short idle tests (E3–E6) did not show it.
- C2 saves only ~8 mA at idle; the value of C2 is the frozen timekeeping in s2idle, not power.
- Downstream programs PMU CPU options at boot (`pwrcal/S5E7870/S5E7870-syspwr.c`,
  `syspwr_init`); mainline does not. cpu0 runs with OPTION `0x01010109` (STANDBYWFE on, SMPEN
  off), cpu1–7 `0x10010101` (MEMPWRDOWN_FEEDBACK off); L2_OPTION 0, UP_SCHEDULER 0. Table in
  docs/cpuidle-plan-2026-10-29.md.
- cpuidle-psci is all-or-nothing over CPUs; staged tests need the state on all CPUs plus a
  default-off debug hack (`CPUIDLE_FLAG_OFF`, loop to `drv->state_count`) and sysfs enabling of
  ≥2 CPUs (hrtimer broadcast owner never enters).
- Tablet state: r11 + `cpuidle.off=1` in pmos.conf (hand edit). r12 (cpuidle off) committed,
  not built. Nothing pushed.
